# Performance Baseline

Auto-generated by `scripts/perf_bench.py`. Records per-category
p50 / p95 / p99 / min / max / mean wall-clock latencies for the
five hot-path categories the BSA plugin family ships. Re-run
via `python3 scripts/perf_bench.py --report=docs/perf_baseline.md`.

**Regression policy** (`scripts/perf_bench.py --check`):
any benchmark whose current p95 is ≥ 2.0× the
baseline p95 fails the check. The threshold is intentionally
loose to avoid noise-driven false positives (system load, GC
pauses, file-cache state) while still catching real algorithmic
regressions (O(n) → O(n²)).

**Numbers ARE machine-dependent.** The committed baseline reflects
the maintainer's laptop (Apple Silicon, macOS). CI runs on GitHub
Actions Linux runners, which are typically 1.5–3× slower per
operation. The 2× regression threshold accommodates this.

## Categories

1. **F5 dispatcher** — `_dispatch()` per-call regex scan over the
   `_DISPATCHER` table. Fires on EVERY canonical write. The
   matching-path bench scans through the table until a regex
   matches; the non-matching-path bench scans the entire table
   without matching (worst case).
2. **validate_canonical_write** — full F5 validation pipeline
   on a representative A59 CSV (~10 rows). Fires on every
   canonical-CSV write.
3. **canon hash** — full `compute_canon_hash.py` run. Fires per
   release + per CI run (canon-hash job). Includes Python startup.
4. **fixture_runner** — full `fixture_runner.py --all --mode=validate`
   run over 8 fixtures. Fires per CI run (fixture-runner job).
5. **CI scan budget** — combined `privacy_scan.py` +
   `security_audit.py`. Fires per CI run (privacy + security jobs).
