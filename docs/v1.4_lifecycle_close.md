## Recurring patterns / lessons

1. **Self-review checklist (per MEMORY) shortened bug-find latency**: impact-analysis / cross-schema / edge-case checks before invoking Codex caught some issues pre-review; Codex still found things missed (esp. security-adjacent cases).

2. **Security hardening through layered defenses** — multiple v1.4.x releases ended up with 4-layer validation:
   - v1.4.10 restore: path validation → type allowlist → analysis/-only scope → root-symlink reject → post-extract is-real-dir verify → atomic-swap rollback.
   - v1.4.7 OCR: shell-injection regex → DecompressionBombWarning escalation → multi-page TIFF iteration → lang-switch detection.

3. **My own CHANGELOG entries tripped my own validators TWICE**:
   - v1.4.8 R2: `` `[t](u)` `` markdown-shorthand inside double backticks parsed as 2 empty code spans + a real link.
   - Same multi-backtick CommonMark gotcha, two Codex rounds to catch.

4. **One-time migration costs accepted** for backward compat:
   - v1.4.4 hash backfill: empty cells when `--keep-raw` wasn't used; operator can `--restage-changed --keep-raw` later.
   - v1.4.9 shell key migration: legacy `bsa-{sid}-sh-{hash}` keys → ONE-TIME duplicate per legacy story; documented in CHANGELOG §Migration with three scenarios + jq one-liner.
